# Сеть

## Где лежат имя сети и пароль

В файле `.env` в корне проекта. В git он не попадает и в исходниках не
упоминается. Формат:

```
WIFI_SSID=MyNetwork
WIFI_PASSWORD=MyPassword
OTA_PASSWORD=UpdatePassword
```

`OTA_PASSWORD` нужен для обновления по воздуху, подробности в [OTA.md](OTA.md).
Пустой пароль означает, что обновление не включится.

Правила разбора: пустые строки и строки с `#` игнорируются, префикс `export`
допустим, значение можно обернуть в кавычки, если в нём есть пробелы. Пробелы
вокруг `=` срезаются. Спецсимволы `$`, `"` и `\` в пароле допустимы.

Шаблон лежит в `.env.example` — он в git есть и значений не содержит.

## Как значения попадают в прошивку

На каждой сборке PlatformIO запускает `scripts/load_env.py`, тот читает `.env`
и генерирует `include/WiFiCredentials.h` с двумя `#define`. Заголовок тоже
в git не попадает. `include/Config.h` подключает его через `__has_include`,
поэтому проект собирается и без него — просто без сети.

Заголовок перезаписывается только при изменении значений, иначе каждая сборка
была бы полной.

Раньше значения передавались флагами `-DWIFI_SSID=...`. От этого пришлось
отказаться: пробел в имени сети рвал аргумент командной строки, а `$` в пароле
съедался подстановкой SCons. В заголовке достаточно экранирования по правилам C.

**После правки `.env` нужно пересобрать и перепрошить плату.** Значения
вшиваются в прошивку на сборке, а не читаются в рантайме.

## Поведение прошивки

Подключением занимается класс `WiFiLink`. Он не блокирует `loop()`, поэтому
демо-анимация идёт всё время, включая попытки подключения. Автомат состояний:

| Состояние | Что происходит |
| --- | --- |
| `Disabled` | SSID пуст, в сеть не идём |
| `Connecting` | идёт попытка, ждём до 15 с |
| `Connected` | связь есть, IP напечатан в лог |
| `Waiting` | пауза 5 с после неудачи или обрыва |

Из `Connected` при пропаже связи автомат уходит в `Waiting` и дальше сам
повторяет попытки без ограничения по числу. Таймауты задаются в
`include/Config.h`.

Штатный автореконнект Arduino отключён (`setAutoReconnect(false)`), чтобы
повторами управлял один класс, а не два механизма одновременно. Запись учёток
во флеш тоже отключена (`persistent(false)`) — она не нужна и изнашивает флеш.

Имя платы в сети — `rgb-panel`, по нему её видно в списке клиентов роутера.

## Диагностика

Смотрите лог на 115200 бод (`pio device monitor`). Раз в секунду печатается
строка вида:

```
шаг 431/1088  RGB 255 140   0  сеть: подключено 192.168.1.42
```

Частые проблемы:

- `сеть: выключен` — `.env` пуст или не найден, смотрите строки `load_env` в
  выводе сборки;
- бесконечное `подключение` / `ожидание` — неверный пароль, либо сеть 5 ГГц:
  ESP32 работает только в диапазоне 2.4 ГГц;
- связь есть, но панель начала мерцать — Wi-Fi и вывод на ленту делят
  прерывания. Если мерцание заметно, снижаем частоту обновления панели или
  переносим вывод на I2S-драйвер FastLED.
